# Серверный фундамент CRM · версия 18

## Принятое решение

Первая рабочая серверная версия совместима с виртуальным хостингом Beget:

- React собирается в статические файлы;
- отдельный PHP API находится в `server/beget-api`;
- данные CRM хранятся в отдельной базе MySQL;
- калькулятор и CRM не используют общие таблицы и учётные записи базы;
- API использует защищённую cookie-сессию, CSRF-токен, проверку Origin, роли и журнал действий.

Такой вариант запускается на существующей инфраструктуре Beget без обязательной покупки VPS. При росте нагрузки API можно перенести, сохранив контракт и предметную модель.

## Что уже заложено

- пользователи и девять серверных ролей;
- сотрудники и закрытые финансовые поля;
- бригады и состав бригад;
- клиенты, объекты и заявки;
- ссылки на проекты EFT SIP Calculator;
- задачи;
- табель;
- история общения;
- учёт состояния интеграций;
- журнал действий и ограничение попыток входа.

Финансовые поля возвращаются API только ролям `owner` и `finance`. Сотрудник может записывать только собственный табель; руководители с правом `attendance.manage` могут вести общий табель.

## Подготовленные API

- `GET ?action=health` — состояние сервера;
- `POST ?action=login` — вход;
- `GET ?action=session` — текущая сессия и права;
- `POST ?action=logout` — выход;
- `GET ?action=bootstrap` — начальные данные с фильтрацией по правам;
- `POST|PUT ?action=employees.save` — сотрудник;
- `GET ?action=attendance.list&month=YYYY-MM` — табель;
- `POST|PUT ?action=attendance.save` — отметка табеля;
- `GET ?action=payroll&month=YYYY-MM` — закрытый расчёт зарплаты.

## Что потребуется в панели Beget

1. Создать отдельный сайт `crm.eftsip.ru`.
2. Создать отдельную базу MySQL и отдельного пользователя базы.
3. Выполнить `server/beget-api/schema.sql` через phpMyAdmin.
4. Разместить `config.local.php` по образцу `config.example.php`.
5. Разместить `.htaccess` по образцу `.htaccess.example`.
6. Через SSH один раз выполнить `create-admin.php`, передав логин и временный пароль в переменных окружения.
7. Создать отдельного ограниченного SSH-пользователя для автоматической публикации.
8. Добавить секреты `CRM_BEGET_*` в GitHub Actions.

## Первичная установка без передачи паролей

В пакет публикации входит одноразовая страница `/api/install.php`. Владелец вводит на ней пароль отдельной базы и создаёт пароль владельца CRM. После успешной записи `config.local.php` установщик автоматически блокирует повторный запуск. Пароли не попадают в Git, GitHub Actions или переписку.

До появления этих доступов GitHub Pages продолжает работать как демонстрация без общей базы.
